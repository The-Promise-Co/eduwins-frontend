# AGENTS — frontend booking work

Append-only memory. Update the status table + log at the end of every phase. Never rewrite history.

## Goal
Tutor booking requests with parent payment held in platform escrow and timed auto-cancel. LiveKit video sessions with per-child join codes.

## Constraints / Decisions
- Use "payment", never "pre-payment".
- Payment window is configurable; countdown starts at `accepted_at`.
- `reserved_at` = parent request creation time.
- Accept/deny require tutor confirmation modal; deny has optional reason (max 1000 chars).
- No mock/fallback data in TS/JS.
- Reuse existing `Modal`, `Button`, `PageHeader`, `VideoPlayer`.
- Full-width layout for all `/app` pages: wrapper is `<div className="space-y-6 pb-12">`. No `max-w-*`/`mx-auto` content wrappers, no per-page horizontal padding — rely on `<main className="p-4 md:p-6">` and `space-y-6` gaps. Follow this religiously.
- Session page layouts use a 2/5–3/5 split on desktop: `grid gap-6 lg:grid-cols-5` with left column `lg:col-span-2` (booking details) and right column `lg:col-span-3` (live preview).
- `GET /bookings/:id` returns `{ booking, parent, teacher, children }`; `useBooking` normalizes this into one enriched `Booking`. Every booking always has `scheduledDate`/`startTime`/`endTime`/`durationHours` — render them directly, no missing-date fallbacks.
- LiveKit for video calls; tokens generated by backend (`POST /livekit/token`).
- Per-child join codes for multi-device access (Google Meet style, no auth required).
- Join window opens 15 min before scheduled start; session auto-ends after `durationHours`.
- End notifications at 20, 10, 5, 2 min thresholds.
- Time display is always 12-hour AM/PM via `misc/utils/time.ts` (`formatTime`/`formatTimeRange`); internal values/payloads stay `HH:MM`/`HH:MM:SS`. Never rely on default `toLocaleTimeString` or `hour: '2-digit'` without `hour12: true`.
- Session preview media is ref-owned (`streamRef`, `videoRef`, `levelBarRef`, `levelTextRef`, plus `*Ref` mirrors of camera/mic toggles) and setup/cleanup are identity-stable — never put `previewStream`/`audioLevel` in effect deps (caused flashing under `reactStrictMode` double-invoke).
- `SessionUiContext` (`useSessionUi`) exposes `inCall`/`setInCall`. While `inCall` is true the app nav is **locked collapsed** (desktop toggle hidden, mobile Menu button hidden) and `main` becomes full-bleed (`flex-1 flex flex-col overflow-hidden p-0`). The session page sets `inCall` only when `joinState === 'connected' && !disconnected && !timing.isEnded`, and resets on unmount.
- The in-call room does NOT use the LiveKit `VideoConference` prefab. It composes primitives: `useTracks([{camera, withPlaceholder}, {screenShare}])` + `ParticipantTile` inside contained boxes (`rounded-2xl border border-white/10 bg-gray-900 aspect-video`), `ControlBar`, and LiveKit in-room `Chat` in a right `w-80` sidebar that is collapsed by default (`LayoutContext.widget.state.showChat`). Keep a `layout` seam for the future layout setting.
